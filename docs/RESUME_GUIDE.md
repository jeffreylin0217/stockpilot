# Resume guide

Project: **StockPilot — Retail Demand & Inventory Analytics | Python, SQL, DuckDB, pandas, Power BI, pytest**

## Safe for the included demo

- Built a Python and SQL retail-demand analytics pipeline processing 1,440 synthetic daily observations across 3 stores and 4 product families, with validation and DuckDB analytical tables.
- Developed a Power BI-ready reporting layer for demand trends, store and product-family performance, promotion analysis and simulated inventory-planning scenarios.
- Implemented configurable moving-average demand forecasts, safety-stock calculations and reorder classifications with automated numerical, pipeline and reporting-export tests.

Use two or three bullets on the actual resume.

Do not present the synthetic dataset as real company data.

Do not describe demand volume as revenue.

Do not claim actual stockout reduction, business adoption, dollars saved or forecast improvement.

## After an actual Power BI report is built

Once the actual Power BI visual report has been created and reviewed, this wording becomes safe:

Developed a Power BI dashboard to surface demand trends, store and product-family performance, promotion patterns and simulated replenishment risk.

## After running public data

Only describe the project as using public retail data after actually loading, validating and reviewing the public dataset.

## Stronger claims

Forecast improvement, simulated stockout reduction, stakeholder adoption or business outcomes require reproducible evidence.

Never invent users or business impact.
